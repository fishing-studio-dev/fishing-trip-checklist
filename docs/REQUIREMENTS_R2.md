最終更新：2026-11-24

## 1. ユーザーの要望（原文の要約）

1. スマホでソナー・海図・魚探を1画面で全部見えるように。
2. 泳がせ釣りのやり方が分からない。表層にベイトがいて曳縄で食わないときに、何をすればよいか分からない。
3. いつでも見返せる全体のチュートリアル。
4. 魚探反応の出方が魚種の手掛かりになるように作り込む。実在の知見を調べて反映する。
5. 漁法ごとに獲れる魚種を増やす（例：一本釣りならイサキ）。
6. 「反応はあるのに食わない」を作る。
   - 例：アジの反応ははっきりあるのに、潮が動き始めた途端に食う。
   - 例：根魚は潮がゆるんだときに釣りやすい。
   - 魚種ごとの生態・釣り・漁の知見から現実的な仕様を考える。
   - 通説が外れる日もある前提にする。
7. 延縄を複数持ち、仕掛けられるようにする。
8. 収支が簡単すぎる。単価や装備の値段を、試遊と計算で適正な値に直す。
9. 四季の移り変わりが分かりにくい。
10. ゲームのゴールが決まっておらず、ゲームの日数を作り込みにくい。

## 4. 深掘りの整理（6つの観点）

### 4.1 範囲と制約

- 固定方針（CLAUDE.md）は維持する。
  - 探す・ポイントを選ぶのは手動、繰り返しの作業は自動。
  - 手動の釣りのミニゲーム・QTE・故障整備・複雑な経営は入れない。
  - ジギングも「しゃくり」は自動にする。プレイヤーが選ぶのは場所・タナの狙い・止める位置。
- 候補や表示は、プレイヤーが聞いたこと・記録したこと・予報からだけ作る（A10）。
  - 「腕前で食いの状態が分かる」のは観測できる材料からの推定とする。生の魚の状態をそのまま見せない。
- 海は（シード, 日）の純関数のまま。1年60日にして、季節・水温は（シード, 年内の日）から決める。年ごとに少し違う（暖かい年・寒い年）。
- 同じ経過時間なら同じ結果（固定ステップ0.1秒）。乱数は `world.rng` とハッシュノイズだけ。

### 4.2 データの形

| 種類 | 内容 |
| --- | --- |
| 暦 | `calendarOf(day)` → { year, season（春夏秋冬）, dayOfSeason, 旬の目安（上旬・中旬・下旬）}。保存はしない（日数から計算）。 |
| 魚種 | 既存の `SPECIES` に次を加える。<br>・季節の出方（いる季節・多い季節）<br>・好む水温<br>・泳層<br>・魚探での映り方（群れの形・濃さ・底からの高さ・群れの動き）<br>・食いの癖（潮の動き・時間帯・明るさ・水温変化への反応）<br>・通説から外れる日の確率 |
| 食いの状態 | 毎日・群れごとに（シード, 日, 群れ）から決まる「その日の機嫌」と、潮・時間帯から計算する。状態として保存しない。 |
| 延縄 | 船の延縄具に「縄の数（1〜3）」を持たせる。<br>航海中の `v.longlines` を配列にし、縄ごとに位置・浸け始め・状態を持つ。 |
| 難易度 | プロフィールに `difficulty`（easy・normal・hard）を持つ。相場・経費の倍率は `data.js` に置く。 |
| 図鑑と記録 | プロフィールに魚種ごとの { 初めて獲った日・場所, 最大の1尾 kg, 累計 } を持つ。 |
| 注文 | 港で日ごとに（シード, 日）から出る。受けた注文はプロフィールに保存し、期限・魚種・量・上乗せを持つ。 |
| 1年の振り返り | 収支の記録（ledger）から年ごとに集計する。前の年の集計は小さな要約として残す。 |
| セーブ | SAVE_SCHEMA を上げて移行を足す。既存の値は変えず、新しい欄に既定値を入れる。読めないデータは消さずに退避する方針は維持。 |

### 4.3 振る舞いと流れ

食わない例は、魚種ごとの「通説」に従う。ただし日によって外れる。

| 魚種 | 食いの通説（本作設定） |
| --- | --- |
| アジ | 潮が止まると反応があっても食わない。動き始めに食いが立つ。 |
| 根魚 | 潮がゆるむと底を取りやすく、釣りやすい。 |
| 青物 | 朝夕のまずめ時に食う。ベイトに付いていると食う。 |

- 理由が読める材料：潮流計の速さ・向きの変化、潮時表の「転流」、群れの形。
  - 例：底べったりで固まっている → 浮いて広がる → 食う。
- 腕前の高い漁法では、操業中に「当たりが遠い」「食いが立ってきた」などの勘が出る。
- 泳がせの流れ：① アジを釣る ② 生け簀に入れる（何尾生きているかを表示）③ ベイトの反応の下・根の周りで止めて開始。
  - 画面の案内で、今どの段階で次に何をするかを出す。
- ジギング：ベイトの下や底近くの反応の上で止めて開始。タナは魚探の反応から自動で取る。

### 4.4 つながり

- 新しい魚種・食いの仕組みは、次のすべてに効く。
  - 魚探の描画（`sounder.js`・`sounderView.js`）
  - ソナーの反応
  - 仲間の話（`reports.js`）
  - 日誌の比較
  - 収支
- 仲間の話は「観測した時刻」と「聞いた時刻」を分けたまま。食いの話（「潮が動くまで全然だった」など）も、その時刻の世界から作る。

### 4.5 品質

- PC・スマホの動作の重さは今と同程度を保つ。スマホ横3列は、描画の間引きで速さを保つ。
- 試験は次のものを足す。
  - 魚種ごとの季節・食いの試験
  - 延縄3本の試験
  - ジギングの試験
  - 難易度と移行の試験
  - 通し試遊（PC・スマホ）
- 収支は、自動の漁師（`tools/econbot.mjs`）で漁法・季節・難易度ごとに日々の稼ぎを測って合わせる。
  - 目安は「ふつう」で次のとおり（R05・R02に合わせて仮置き。測ってから決め直す）。
    - 釣れない日は赤字。
    - まともな日でも黒字は数千〜1万G台。
    - 中型漁船に手が届くのは1季節目の終わりごろ。
    - 装備が全部そろうのは1年がかり。

### 5.2 食いの通説（実在の知見 → 本作の食いの仕組み）

自然相手なので、どの通説も毎日は当てはまらない。群れごと・日ごとに「機嫌」を決め、一部の日は通説が外れる。
- 潮止まりなのに食う日がある。
- 潮が動いても食わない日がある。

## 6. 仕様案（第1段：海と魚）

### 6.1 暦

- 1年60日、1季節15日、ゲームの1日は実際の約6日（1か月＝5日）。
- 季節は「海の季節」で、陸より1か月ほど遅れる。

| 季節 | 月 | 水温 |
| --- | --- | --- |
| 春 | 4〜6月 | 上がる時期：15→22℃ |
| 夏 | 7〜9月 | 高い時期：23→27℃ |
| 秋 | 10〜12月 | 下がる時期：25→18℃ |
| 冬 | 1〜3月 | 低い時期：17→14℃ |

- 1日目は春の1日目（4月上旬）。港と海の上に「春 3日目（4月中旬）・水温16.2℃」と出す。
- 季節が変わる朝に、港で知らせを出す。
  - 例：「夏になった。イサキの群れが瀬に付き始めたと源さん」
  - 港と海の景色（空・海の色・日の出の時刻・日の長さ）も季節で変える。
- 今の序盤の筋書き（1〜7日目）は、春の水温（15〜17℃）に合わせて数値を直す。サワラの来る水温も季節に合わせて直す。

### 6.3 魚探の映り方

- 魚種ごとに次を持たせ、魚探・ソナーの描画をこれで分ける。
  - 群れの形：雲・帯・団子・柱・点々・「へ」の字・斜めの線
  - 底からの高さ
  - 密度
  - 群れの乱れ
- 大型魚の「へ」の字は、実際の魚探と同じ原理で描く。
  - 1尾ずつの位置を（シード, 群れ, 番号）のハッシュで決める。
  - 船が近づくと遠く、真上で近く映る。
- ES-1では細かい違いが潰れ、ES-2・SV-1では分かれて見える（装備の意味が増える）。

### 6.4 食いの仕組み

食いの強さは、次の掛け算で決める。

食い = 潮の局面 × 時間帯 × 水温 × 季節 × 天候の後 × その日の機嫌

| 要素 | 内容 |
| --- | --- |
| 潮の局面 | 止まり・動き始め・効いている・緩み始め。潮流の速さとその変化から決める。潮時表と潮流計で読める。 |
| 時間帯 | 朝まずめ・日中・夕まずめ・夜 |
| 水温 | 魚種ごとの好む水温からの外れ |
| 季節 | 旬・産卵前の荒食い・オフ |
| 天候の後 | 時化・大雨の翌日 |
| その日の機嫌 | 群れごと・日ごとにハッシュで決める。約2割の日は、潮の通説が当てはまらないか逆になる。 |

- 群れの形も食いに合わせて変える。
  - 食わないアジ：底べったりに固まる。
  - 食い始め：浮いて広がる。
- 腕前（その漁法のLv5以上）で「当たりが遠い」「食いが立ってきた」などの勘を出す。
  - 勘は、自分が見た反応の濃さと実際の当たりの数から作る（観測できる材料だけ、A10）。
  - Lvが高いほど早く・正確に出る。
- 仲間の話にも食いの様子を入れる。
  - 例：「北の瀬は反応ばっかりで朝は全然。10時の潮の動き始めから急に食った」
  - その時刻の世界から作る。
